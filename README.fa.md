فرض کن دو تا سرور داری، یکی ایران و یکی خارج، و می‌خواهی همیشه بهترین تانل بینشان برقرار باشد — بدون اینکه هر بار دستی سر و کله بزنی. رهیاب دقیقاً همین کار را می‌کند.

داشبورد و مانیتورینگ روی یک سرور می‌نشیند (بهش می‌گوییم هاب)، تانل بین هر دو سرور ساخته می‌شود، و یک نگهبان روی سرور سمت ایران مواظب تانل است: اگر قطع شد برش می‌گرداند، و اگر لازم شد پروتکل را عوض می‌کند.

یک خط قرمز هم دارد که عوض نمی‌شود: رهیاب فقط تانل را می‌سازد، زیر نظر می‌گیرد و برمی‌گرداند. به هیچ پنل PasarGuard، کانفیگ، نود و یوزرش، از هیچ راهی، دست نمی‌زند.

## ✨ چه کار می‌کند؟

- 🔍 **بنچمارک واقعی** — برای هر پروتکل، تأخیر، جیتر، قطعی و توان را روی ترافیک واقعی اندازه می‌گیرد، نه روی عددهای فرضی. نتیجه هر پروتکل جدا ذخیره می‌شود.
- 🏆 **انتخاب با عدد واقعی** — پروتکل‌ها با میانه همان اندازه‌گیری‌ها رتبه‌بندی می‌شوند. هر کدام در عمل بهتر بوده، همان انتخاب می‌شود.
- 🚀 **نصب با یک دستور** — نصب‌کننده هاب یا نود را نصب می‌کند، BBR را روشن می‌کند و گواهی پنل را می‌گیرد (با دامنه یا آی‌پی).
- 🔄 **سوییچ با یک کلیک** — از داخل داشبورد می‌شود تانل زنده را به پروتکل دیگری برد. قبلش تأیید می‌خواهد، و اگر پروتکل تازه در بررسی سلامت رد شود، خودش به قبلی برمی‌گردد.
- 🛡️ **فیل‌اور با حافظه** — نگهبان اول همان تانل را برمی‌گرداند، بعد سراغ کاندیدهای بعدی می‌رود تا یکی سالم شود. مدار شکن هم جلوی سوییچ‌های پی‌درپی را می‌گیرد؛ ضمناً تلاش ناموفق سهمیه را مصرف نمی‌کند، چون تانل همان‌جا که بوده مانده.
- 👁️ **داشبورد زنده** — کارت جفت‌ها، گیج‌های سرور (CPU، حافظه، دیسک، آپتایم)، پینگ و توان واقعی، تایم‌لاین رویدادها، و یک خط چیپ برای پروتکل‌ها که چراغ سبز چشمک‌زن، پروتکل فعال را نشان می‌دهد. نمودارها فقط از داده‌ای کشیده می‌شوند که واقعاً جمع شده؛ اگر داده‌ای نباشد، نمودار هم چیزی نشان نمی‌دهد و عددی ساخته نمی‌شود.
- 🔐 **دسترسی فقط با کلید** — هاب فقط با کلید SSH به سرورها می‌رسد؛ هاست ناشناس رد می‌شود. پسورد اپراتور با PBKDF2 هش می‌شود و سشن‌ها هم هش‌شده‌اند.

## 🧭 اصول ایمنی

۱. **فقط یونیت‌های خودش.** این ابزار فقط سرویس‌ها و رول‌های فایروالی را می‌سازد، ری‌استارت و حذف می‌کند که تگ خودش را دارند. تانل‌ها و سرویس‌هایی که از قبل روی سرور بوده‌اند، هیچ‌وقت دست‌کاری نمی‌شوند.
۲. **توقف هنگام تردید.** اگر بررسی سلامت رد شود، سوییچ پیش از جابه‌جایی ترافیک می‌ایستد؛ اورلی ناموفق هم کریر زنده را دست‌نخورده می‌گذارد.
۳. **بازگشت خودکار.** اگر پروتکل تازه در راستی‌آزمایی رد شود، پروتکل قبلی خودکار برمی‌گردد.
۴. **هیچ سکرتی داخل ریپو نیست.** کلیدها، پسوردها و توکن‌ها بیرون از ریپو هستند؛ کلید خود هاب git-ignored است و غیبتش از همه کامیت‌ها راستی‌آزمایی شده.
۵. **هیچ یکپارچه‌سازی‌ای با پنل نیست.** عمداً به هیچ سامانه مدیریت یوزر دسترسی ندارد — خروجی‌اش یک تانل سالم است، و اینکه روی آن تانل چه می‌گذرد، کار خود اپراتور است.

## ⚡ شروع سریع

**چی لازم داری:** دو سرور تازه با Debian یا Ubuntu، پایتون ۳٫۱۱ به بالا، و دسترسی روت روی هر دو.

### روش پیشنهادی: جریان اتصال (بدون تایپ آی‌پی)

**قدم ۱ — روی سرور مستر.** نصب‌کننده را دانلود و اجرا کن، بعد گزینه مستر را بزن:

```bash
curl -fsSL -o /tmp/install-rahyaab.sh https://raw.githubusercontent.com/irluca/Rahyaab/main/install.sh
bash /tmp/install-rahyaab.sh
```

نصب‌کننده اول می‌پرسد «این سرور مستر است یا نود؟» — گزینه مستر را بزن. خودش هاب را نصب می‌کند، BBR را روشن می‌کند، ازت می‌پرسد گواهی را با دامنه می‌خواهی یا آی‌پی، مستر را ثبت می‌کند و آخرش یک دستور اتصال یک‌خطی چاپ می‌کند. همان یک خط را نگه دار.

دو نکته همین‌جا: اگر موقع گواهی گزینه «بعداً» را بزنی، دستور اتصال چاپ نمی‌شود؛ اول باید گواهی بگیری، بعد از منوی نصب‌کننده (مدیریت، بعد نمایش دستور اتصال) دستور تازه را بگیری. و اینکه کد اتصال فقط یک بار مصرف می‌شود؛ اگر دستور تازه‌ای چاپ کنی، قبلی می‌سوزد.

**قدم ۲ — روی سرور نود.** همان یک خطی را که مستر چاپ کرده، روی سرور نود پیست کن و اجرا کن. نود خودش را نصب می‌کند، اثر انگشت گواهی مستر را — که داخل همان دستور است — چک می‌کند که واقعاً با همان مستر خودت حرف می‌زند، و وصل می‌شود. بعدش مستر در پس‌زمینه جفت را می‌سازد، تانل اول (GRE) را مستقر می‌کند و نگهبان را نصب می‌کند. کاری از تو نمی‌خواهد؛ چند دقیقه طول می‌کشد.

**قدم ۳ — داشبورد.** مرورگر را روی **https://YOUR-SERVER-IP:8890** باز کن (به‌جای YOUR-SERVER-IP آی‌پی سرور مستر را بگذار) و حساب اپراتور را بساز. فرم راه‌اندازی فقط وقتی نشان داده می‌شود که هنوز حسابی نباشد. بعد ببین جفت چطور بالا می‌آید: باید GRE وصل و نگهبان سالم نشان داده شود.

مرورگر بار اول برای گواهی هشدار می‌دهد؛ این طبیعی است، مخصوصاً در مسیر آی‌پی که گواهی self-signed است. اثر انگشت گواهی را نصب‌کننده موقع نصب چاپ می‌کند؛ با همان مقایسه کن و بعد تأیید کن.

### روش غیرتعاملی (برای اسکریپت و اتوماسیون)

```bash
bash /tmp/install-rahyaab.sh --role master --bbr --ip-cert --yes                                  # مستر + BBR + گواهی self-signed آی‌پی (با تمدید خودکار) + چاپ دستور اتصال
bash /tmp/install-rahyaab.sh --role hub --bbr --ip-cert --yes                                    # هاب + BBR + گواهی self-signed آی‌پی (با تمدید خودکار)
bash /tmp/install-rahyaab.sh --role hub --bbr --domain panel.example.com --email you@example.com --yes  # هاب + Let's Encrypt
bash /tmp/install-rahyaab.sh --role node --bbr --yes                                              # نود (بدون داشبورد)
bash /tmp/install-rahyaab.sh --print-join                                                          # چاپ دستور اتصال تازه (فقط روی مستر)
bash /tmp/install-rahyaab.sh --join <host> <token> <fingerprint>                                   # اتصال نود با سه تکه دستور اتصال
```

### روش دیگر: راه‌اندازی کامل از سمت مستر (دو سرور خام، با یک دستور)

اگر نمی‌خواهی روی نود چیزی پیست کنی، روی سرور هاب، با دسترسی روت، این را بزن:

```bash
bash /tmp/install-rahyaab.sh --full-setup <node-host> --bbr --ip-cert --yes
```

این دستور هاب را نصب می‌کند، BBR را روشن می‌کند، گواهی پنل را می‌گیرد، کلید هاب را روی نود نصب می‌کند (پسورد روت نود فقط یک بار همان‌جا پرسیده و هیچ‌جا ذخیره نمی‌شود)، نود را از راه دور نصب می‌کند، جفت را ثبت می‌کند، تانل اول (GRE) را اندازه می‌گیرد و مستقر می‌کند و نگهبان را رویش نصب می‌کند. با `--protocol` می‌شود پروتکل تانل اول را عوض کرد (پیش‌فرض GRE است) و با `--pair-name` اسم جفت را گذاشت (پیش‌فرض «جفت اصلی» است). بعدش داشبورد را باز کن و حساب اپراتور را بساز — آن قدم در خود داشبورد می‌ماند و نصب‌کننده هیچ حسابی نمی‌سازد و به PasarGuard دست نمی‌زند.

**چند نکته که موقع کار به دردت می‌خورد:** Let's Encrypt برای آی‌پی خالی گواهی نمی‌دهد، پس مسیر آی‌پی self-signed است و تایمر روزانه پیش از انقضا خودش تمدیدش می‌کند. اجرای دوباره نصب‌کننده امن است: دیتابیس و گواهی‌های موجود هیچ‌وقت بازنویسی نمی‌شوند. اگر جفتی از قبل راه‌اندازی شده باشد، اتصال تازه به‌تنهایی آن را دوباره مستقر نمی‌کند. فورک خصوصی برای مسیر دانلود به `GITHUB_TOKEN` (توکن خواندنی fine-grained) نیاز دارد، یا می‌شود با `--local` از روی کپی آپلودشده کد نصب کرد.

## 🧪 تست

کل قرارداد رفتاری پروژه یک سوئیت آفلاین است (بدون نیاز به هیچ سروری):

```bash
python -m pytest orchestrator/ hub/ -q
# ۲۱۹ تست — بنچمارک، فیل‌اور، گاردهای ایمنی، بهداشت اینستالرها، ویزارد و جریان اتصال
```

## 🗂️ ساختار

```
orchestrator/     موتور اثبات‌شده: بنچمارک، استقرار، نگهبان، فیل‌اور، هشدارها، سوئیت آفلاین
agent/            ایجنت مقیم Rust (فقط ری‌استارت، فقط گزارش)
hub/              رجیستری ناوگان، جفت‌ها، JSON API، کنترل نگهبان، جاب‌ها، لاگین
dashboard/        داشبورد تک‌صفحه‌ای تازه (راست‌به‌چپ، Vazirmatn، تم تیره)
install.sh        نصب‌کننده سرور (مستر/نود، جریان اتصال، BBR، گواهی‌ها، به‌روزرسانی، حذف)
*.sh              جفت‌های نصب مستقل (iran-*.sh / foreign-*.sh)
docs/             ران‌بوک‌ها (فازها، نظرسنجی پنل)
```

## 🗺️ وضعیت

- **فاز ۱ (پی‌ریزی)** — تمام شد ۲۶ اکتبر ۲۰۲۶: موتور و ایجنت پورت شدند، سوئیت سبز.
- **فاز ۲ (هاب)** — تمام شد ۲۶ اکتبر ۲۰۲۶: JSON API با پایتون خالص، CRUD ناوگان و جفت، کنترل نگهبان، جاب‌ها، رویدادها.
- **فاز ۳ (داشبورد)** — تمام شد ۲۶ اکتبر ۲۰۲۶: داشبورد تازه، سرو شده توسط خود هاب.
- **فاز ۴ (نصب لایو + تست‌ها)** — تمام شد ۲۶ اکتبر ۲۰۲۶: هاب روی سرور ایران، جفت لایو پذیرش شد، تست‌های لایو از روی API هاب پاس شدند و سوییچ اورلی هم به‌صورت لایو اثبات شد (کریر به کریر و کریر به اورلی).
- **فاز ۵ (ریپو + تگ)** — تمام شد ۲۷ اکتبر ۲۰۲۶: ریپوی عمومی، تگ `v1.0`.
- **نصب‌کننده ۱٫۰٫۲** — تمام شد ۲۷ اکتبر ۲۰۲۶: روی هر دو سرور لایو تست شد (نود + هاب، BBR، حفظ گواهی آی‌پی، بدون دست خوردن نگهبان و تانل).
- **نصب‌کننده ۱٫۱٫۰ و ۱٫۱٫۱** — تمام شد ۲۷ اکتبر ۲۰۲۶: کلید هاب روی خود هاب ساخته می‌شود و دیگر پیش من نیست؛ کلید خصوصی موجود هیچ‌وقت بازنویسی نمی‌شود.
- **نصب‌کننده ۱٫۲٫۰** — تمام شد ۲۷ اکتبر ۲۰۲۶: نصب نود از راه دور از روی سرور هاب، با کلید هاب.
- **نصب‌کننده ۱٫۳٫۰** — تمام شد ۲۷ اکتبر ۲۰۲۶: ویزارد راه‌اندازی کامل با یک دستور (هاب + نود + جفت + تانل اول + نگهبان).
- **نصب‌کننده ۱٫۴٫۰** — تمام شد ۲۷ اکتبر ۲۰۲۶: جریان اتصال مستر/نود؛ دیگر لازم نیست آی‌پی تایپ کنی، فقط یک خط کپی‌پیست. تست زنده‌اش با ریبیلد انجام می‌شود.
